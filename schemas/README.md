Schemas are **JSON Schema Draft 2020-12**, versioned by major directory. AIS point, stationary candidate and run manifest represent current prototype formats (CSV must be type-coerced to validate). Source snapshot is a proposed future contract. A new product or API must not claim schema conformance until serialized-output tests pass. Every event currently has confidence=unvalidated.

`multi-day-run.schema.json` is `multi-day-1.1` and allows 2 to 16 input files. A `multi-day-1.0` document is not this schema. `resources.memory_bound` is required. Its policy is `fixed-sqlite-heap-v1`: SQLite cache 8192 KiB, soft heap request 8388608 bytes, `mmap_bytes` 0, `temp_store` `FILE`, and `grows_with_input_rows` false. `soft_heap_limit_enforced` is a boolean, or the string `unknown` when `PRAGMA compile_options` cannot be read. True means this SQLite lists `ENABLE_MEMORY_MANAGEMENT`. The enforced pin is the cache, the disabled memory map, and the file temp store. Scratch disk is still the separate `limits.max_scratch_mib` cap. The object describes resource limits. It does not validate a candidate as a berth, anchorage, wait, or port call.

The SPEC-004 track-zone-evidence and track-zone-context-receipt contracts cover an **unverified geometric observation report**, never independently confirmed anchorage or berth/waiting events. Source receipt hashes are verified locally; authoritative source dates and reuse rights are NOT inferred.

SPEC-004 historical geometry documentary contracts: noaa-enc-documentary-evidence.schema.json and geometry-vintage-audit.schema.json. Both deliberately lack any status that could automatically approve historic polygons or operational maritime events.

The fr-official-text-triage.schema.json contract preserves source hashes and mandatory legal status NOT_DETERMINED for four official Federal Register Part 110 texts; keyword matching does not certify a section amendment or historical anchorage perimeter.

`govinfo-lsa-dec-jan-comparison.schema.json` is the opt-in December 2023 / January 2024 GovInfo LSA index comparison. Each official PDF URL is a const for one fixed HTTPS GovInfo path. `legal_effect_on_study_date` is const `NOT_DETERMINED`, `rights_status` is const `review_required`, and AIS spatial joins stay false. `harborlens_version` is required and records the package version that wrote the file. Each month's PDF SHA-256, byte length, and page count are const pins (December 2023: 117 pages; January 2024: 82 pages). The page count cannot exceed 299 (`MAX_PDF_PAGES`). A matching proposed-rule page list is not a legal determination, a berth, an anchorage, a wait, or a port call. This file lives in `schemas/v1/` with the other research contracts. It is not copied into `src/harborlens/schemas/`. setuptools packages `src/harborlens/schemas/v1/*.json`: the rights register and the three release-gate schemas named below. Other research contracts stay in `schemas/v1/` only.

`source-rights-register.schema.json` is the contract for `docs/data/rights-register.json` and for `python -m harborlens.rights` (SPEC-003, FR-010, NFR-013, NFR-019, BR-015, BR-016). The runtime copy is `src/harborlens/schemas/v1/source-rights-register.schema.json`, byte-identical, loaded with `importlib.resources` only. A reviewed `reviewed_at_utc` must be an ASCII `YYYY-MM-DDTHH:MM:SS` timestamp with no fraction or 1 to 6 fractional digits, then `Z` or `+00:00`. The parser builds the clock from those fields and does not call `fromisoformat`, so Python 3.10 and 3.12 accept the same strings. A string that only ends in `Z` does not match. Seven fractional digits, another offset, a non-ASCII digit, and an impossible calendar time do not grant. https URLs use an ASCII hostname. A port, when present, is 1-65535. Punycode (`xn--`) is accepted. A backslash, a C0 or C1 control, or DEL does not match. IPv6 literals, raw IDN hostnames, userinfo, an uppercase scheme, and any whitespace, including a trailing path space, fail closed. Whitespace-only reviewer or attribution text fails when `decision` is `reviewed`. A file that starts with a UTF-8 BOM is a load error (`Rights register has a UTF-8 BOM`), not an approved status. No checked-in source is approved.

`erddap-ais-source.schema.json` is the sidecar written by `harborlens-fetch-erddap`. `noaa-archive-extract-source.schema.json` is the sidecar written by `harborlens-extract-noaa-archive`. Both require the existing `rights_status` field and allow an optional `rights_review` object with the same shape as `source-rights-receipt.schema.json`. Adapters do not load these files at runtime, so they are not copied into `src/harborlens/schemas/v1/` and `read_packaged_release_schema` refuses those names. A schema-valid sidecar is not a source approval. With the checked-in register every adapter stays `rights_status=review_required`.

Serialized-output tests (`tests/test_contracts.py`) validate the real CLI exports: the run manifest as written, `stationary_candidates.csv` read back with `harborlens.ais.read_candidates_csv` (typed `duration_min`, `point_count`, `centroid_lon`, `centroid_lat`, `maximum_distance_m`) against `stationary-candidate.schema.json`, and each single-file GeoJSON Feature against `stationary-candidate-feature.schema.json`. Manifests carry `code_version`; the package version is part of `run_id`.

`release-verification-result.schema.json` is the stdout contract of `harborlens-verify-release`. `verified: true` means the signed aggregate and the pinned rights snapshot matched the supplied trust anchors. It does not certify AIS observations, source rights, anonymity, or a berth, anchorage, wait, or port call.

`harborlens-release-summary` writes a `public-summary-v0.1` file. `public-summary.schema.json` is that staged document. `publication-review.schema.json` is the signed review object inside it. Copies of these three release-gate schemas live at `src/harborlens/schemas/v1/` and are byte-identical to the files in `schemas/v1/`. `read_packaged_release_schema` loads them with `importlib.resources` only. A name outside that allowlist is refused. A schema file next to a virtualenv is not consulted. `reviewed_at_utc` on a release review is ASCII `YYYY-MM-DDTHH:MM:SS` with no fraction or 1 to 6 fractional digits, then `Z`. The parser builds the clock from those fields and does not call `fromisoformat`, so Python 3.10 and 3.12 agree. `+00:00` is rejected here; the rights register still allows `Z` or `+00:00`. A comma fraction, seven fractional digits, another offset, a non-ASCII digit, hour 24, and a date-only value are rejected. Both commands accept a matching timestamp only when it is not older than 30 days and not more than 5 minutes ahead of the checker clock. The 5 minutes are a fixed clock-skew allowance, not a configuration knob. These contracts do not approve source rights.

`evaluation-report.schema.json` is `evaluation-v0.2`. `validation_status` is const `unvalidated`. `label_provenance` is `synthetic` or `unspecified`. The `caveat` const depends on that provenance: both strings say the labels are not independent ground truth and that the report makes no accuracy claim, and the unspecified string says the label provenance is unspecified. `warning` is a string and is not a const. The current warning says that agreement with labels at any evidence level, including L3, is not validated performance while `validation_status` is `unvalidated`. `mixed`, `unknown`, and unlabeled counts stay under `coverage.excluded`. An `evaluation-v0.1` document does not validate. `read_evaluation_report` raises `EvaluationReportError` for that version. No v0.1 reader is maintained. The report does not approve a source and does not make a stationary candidate a berth, anchorage, wait, or port call.

`label-sample.schema.json` is `label-sample-v0.2`. Each key item has `transceiver_class` (`A`, `B`, or `absent_or_unknown`) and a `stratum` whose last component is that class. Candidate keys are `duration|censoring|vessel_group|transceiver_class`; negative keys are `negative|vessel_group|transceiver_class`. `stratification.all_non_empty_strata_drawn` is false when the requested size is smaller than the number of non-empty strata (full cross-cell coverage is then impossible). Per-class coverage is still guaranteed when the request is at least the number of classes present in the frame. `absent_or_unknown` is a real stratum for a missing, blank or other class, not a dropped row. v0.1 manifests do not validate. The annotator CSV is not this schema and does not carry the class.
