# SPEC-003: Independent event validation and data lineage

**Status:** PARTIAL — local provenance, labeling and evaluation tooling; no labels collected · **Created:** 2026-11-08; **Updated:** 2026-11-12.

## Problem / user story

A third party needs to reproduce each metric and assess error against independent real-world labels.

## Linked requirements

FR-010, FR-013..014; BR-012..013; NFR-010, NFR-012

## Acceptance criteria

1. **Given** a source snapshot and derived run; **when** an analyst requests provenance; **then** dataset URL/version, hash, method, parameters, rights, exclusions and output fingerprints are shown.
2. **Given** expert-labeled positive, negative and unknown cases; **when** validation runs; **then** confusion matrix, precision/recall/F1, MAE and coverage by cohort are reported.
3. **Given** only aggregated BTS metrics exist; **when** a comparative report is produced; **then** the document states aggregate trend validation cannot prove individual event truth.
4. **Given** a verified run; **when** a labeling sample is drawn with a seed; **then** the same seed reproduces the same blinded sheet, every non-empty stratum (duration band × censoring × vessel group × transceiver class `A` / `B` / `absent_or_unknown`, plus negative movement intervals stratified by vessel group × transceiver class) is represented when the requested count covers those strata, every transceiver class present in the frame is still represented when the requested count is smaller than the number of strata but at least as large as the number of classes, `stratification.all_non_empty_strata_drawn` is false in that short-request case, missing or invalid transceiver values stay in `absent_or_unknown` rather than being dropped, and the candidate/negative key exists only in the sampling manifest.
5. **Given** two completed sheets from different annotators; **when** agreement is computed; **then** raw agreement, Cohen's kappa (seven labels and collapsed classes), the inter-annotator confusion matrix and every disagreement are reported, `unknown` labels are counted separately, and the report states that agreement is not accuracy.
6. **Given** an adjudicated label file for a sample drawn from a verified run; **when** `harborlens-evaluate` runs; **then** TP/FP/FN/TN, precision, recall, F1 and specificity with Wilson 95% intervals, a stratum-weighted precision, cohort metrics (evidence level, vessel group, censoring) and boundary MAE/median error for uncensored true positives are reported; `mixed`, `unknown` and unlabeled units are counted separately and never as correct; and the report states whether any L2 labels were used.

## Non-goals and safety

No operational navigation, autonomous control, live vessel tracking, regulatory certification, unverified berth or waiting-time claims, or unauthorized licensed data redistribution. A synthetic fixture is not independent validation.

## Definition of Done

Accepted and reviewed requirements, passing boundary/negative tests, documented source rights, updated JSON schema and traceability, explicit uncertainty and reproducible evidence attached to the linked issue/PR.

## Incremental acceptance: human-reviewed, aggregate-only local release (FR-010 / BR-015..016)

7. **Given** an acquisition receipt with source/version/source-file hash and a verified single-file run; **when** publication of a coarse aggregate is requested; **then** the exporter independently checks current per-purpose source rights and produces no release if rights are pending, prohibited or mismatched.
8. **Given** reviewed rights and a privacy/science assessment of an exact proposed summary digest; **when** local release staging runs; **then** only the allowlisted numeric summary and audit evidence are written, with no raw AIS, MMSI identifiers, positions, timestamps or individual event details; an absent, stale, date-only, future-dated, or mismatched human decision fails closed (exit 2, nothing written). `reviewed_at_utc` is an RFC3339 UTC date-time accepted only from 30 days before the checker clock through 5 minutes after it, inclusive. Those 5 minutes are a fixed clock-skew allowance, not a configuration knob. The command calls `prepare_summary` once and stages that summary.
9. **Given** corrupt source/manifest/sidecar evidence, truncated output, a verified cleaned-file recount below 100 retained observations or 10 MMSI groups, a manifest hash or `written` / `vessels` count that disagrees with `houston_clean.csv`, or a cleaned file larger than the 256 MiB recount ceiling; **when** the release is requested; **then** no output is written. The cleaned CSV is read once into that bounded buffer. SHA-256 and the recount use those exact bytes, and there is no second open. The floors are decided on that recount. This is **not** general-purpose output-export enforcement or proof of anonymity.

10. **Given** an otherwise valid approval JSON; **when** publication is attempted without a valid Ed25519 signature from the out-of-band pinned reviewer key and expected identity; **then** the release is denied. Altered signed claims, a signature that omits the `harborlens.publication-review.v1` domain separator, changed trust key, expired review, a non-finite canonical number, or missing cryptographic dependencies also fail closed. A locally supplied trust root is not the same as enterprise-enforced reviewer authorization.

11. **Given** a staged signed aggregate release and no original AIS files; **when** an independent reviewer supplies a trusted reviewer key, its SPKI SHA-256 fingerprint, the expected reviewer identity, an independently pinned rights-register snapshot, and the expected study scope; **then** `harborlens-verify-release` checks the exact release structure, the publisher canonical summary hash (`allow_nan=False`), the domain-separated Ed25519 signature (`harborlens.publication-review.v1`), review recency (a date-only timestamp fails; the timestamp must be an RFC3339 UTC date-time not older than 30 days and not more than 5 minutes ahead of the checker clock; the 5 minutes are a fixed clock-skew allowance, not a configuration knob), acknowledgments, rights status for the same source/version/purpose, and the recounted aggregate floors (100 retained observations and 10 MMSI groups). Pinned digests and fingerprints are compared with `hmac.compare_digest`. A scanned count taken from a manifest does not satisfy those floors alone. A mismatched digest, a `0.2.0.dev4` signature, and a missing `cryptography` install fail closed (exit 2, nothing written). This verifier does not recount `houston_clean.csv`. The Ed25519 review attests the counts. `verification_scope` is `signed_release_and_pinned_rights_only`. A signed retained count inflated above those floors is not detectable without the CSV; anyone holding that file must recount on the release path. The result explicitly denies proving historical AIS observations, legal permission, anonymity, or a berth, anchorage, wait, or port call.

12. **Given** a local rights register or an ERDDAP or archive-extract sidecar; **when** the register is loaded or the sidecar is checked against its schema; **then** a UTF-8 BOM, YAML, a review timestamp that is not a real UTC `YYYY-MM-DDTHH:MM:SS` value with `Z` or `+00:00`, a URL with whitespace, an IPv6 literal, a raw IDN hostname, a case-variant status, or whitespace-only evidence does not produce an approved status. Punycode hostnames remain acceptable. Every checked-in source stays `rights_status=review_required` for `research`, `public_aggregates`, and `commercial`. The ERDDAP and archive-extract schemas accept the writer output, including an optional rights receipt, and reject a receipt that claims `reviewed_record` while the status is still `review_required`.
13. **Given** a release-review `reviewed_at_utc` on Python 3.10 or 3.12; **when** `harborlens-release-summary` or `harborlens-verify-release` reads it; **then** both accept ASCII `YYYY-MM-DDTHH:MM:SS` with no fraction or 1 to 6 fractional digits, then `Z` only, and both reject `+00:00`, another offset, a comma fraction, seven fractional digits, a non-ASCII digit, hour 24, and a date-only value. The 30-day and 5-minute window is unchanged. This grammar is narrower than the rights-register clock, which also allows `+00:00`.
14. **Given** an adjudicated label file for a sample drawn from a verified run; **when** `harborlens-evaluate` runs; **then** the report is `evaluation-v0.2`, `validation_status` is `unvalidated`, and `label_provenance` is `synthetic` only when `--label-provenance synthetic` is passed and is otherwise `unspecified`. The `caveat` states that the labels are not independent ground truth and that no accuracy claim is made. When provenance is unspecified, the caveat says the label provenance is unspecified. The `warning` says that agreement with labels at any evidence level, including L3, is not validated performance while `validation_status` is `unvalidated`. Any other `--label-provenance` value exits 2 and writes nothing. An `evaluation-v0.1` report is not readable: `read_evaluation_report` raises `EvaluationReportError`. No `evaluation-v0.1` reader is maintained. This is a reproducibility harness on synthetic labels. It does not run the real-label pilot.
15. **Given** a text cell on the label sheet that matches `^'*<ignorable>*<trigger>`, including fullwidth `＝` `＋` `－` `＠` and U+FEFF or U+200B before a trigger; **when** `harborlens-label-sample` writes the sheet; **then** the cell is prefixed with one ASCII apostrophe. The same module neutralizes `vessel_type` and `nav_status` in `houston_clean.csv` and `vessel_type` in stationary-candidate CSVs. `vessel_type_mode`, `annotator_id`, `evidence_sources`, `notes`, and `adjudicator_id` are label-sheet text. `sample_id`, `mmsi`, `observed_points`, `centroid_lon`, `centroid_lat`, `start_utc`, `end_utc`, censoring flags, the annotation enums, and `true_start_utc` / `true_end_utc` are validated and written unchanged. A negative longitude such as `-95.1` is not prefixed. A contract value that fails its check raises `AISInputError`, the CLI exits 2, and no sheet, `.partial`, or sampling manifest is written. The sampling key stays JSON. GeoJSON is not neutralized.
16. **Given** that sheet, an adjudicated CSV, or `houston_clean.csv`, read by `harborlens-label-agreement`, `harborlens-evaluate`, or the release recount; **when** a text cell carries the neutralization prefix; **then** exactly one leading apostrophe is removed only when the cell matches `^'+<ignorable>*<trigger>`. `'abc` is unchanged. `'=x` is stored as `''=x` and read back as `'=x`. A leading apostrophe on a contract column raises `AISInputError` and is not converted to a number, timestamp, or enum. A contract column that comes back carrying a trigger without that apostrophe, and that fails its contract, raises `AISInputError`; the CLI exits 2 and writes nothing. Annotators import the sheet with columns as Text and re-validate it after editing.
